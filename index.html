What is AI, really?

Normal programs follow rules that people write. Machine learning works the other way round. You build a machine full of adjustable numbers, show it examples, and tune the numbers until its answers match.

Why not just write the rules?

Nobody can write down every rule for "understand a sentence" or "spot a cat in a photo". There are too many and they are fuzzy. A learning machine finds its own rules, and they end up stored in its numbers.

A language model does one job: read some text and guess what comes next. To write an answer, it guesses one piece, adds it to the text, and guesses again.

Watch it write

The model starts from nothing and adds one piece at a time until it writes a full stop.

At every step it gives each possible next piece a probability, then picks one at random by those odds. ChatGPT does the same with a vocabulary of 100,000 or more pieces.

2

Turning text into numbers

A network can only do arithmetic, so text has to become numbers. A tokenizer splits text into pieces called tokens and gives each one an ID from a fixed list, the vocabulary.

GPT models use Byte-Pair Encoding (BPE). It starts from single letters and keeps gluing the most common neighbouring pair into a new token.

Giving each token a meaning

An ID like 45 is only a label. So the model's first move is to look the ID up in a table and swap it for a row of 10 numbers, called an embedding. The rows start out random. Training nudges them until tokens used in similar ways get similar numbers.

4

One neuron, every number shown

A network is built from neurons. Each one does three small things:

  1. Multiply each input by its own weight. A negative weight argues against.
  2. Add everything up, plus one extra number, the bias.
  3. Squash the total with tanh, which turns any number into one between −1 and +1.

This neuron decides whether to go to the park.

How a neuron learns

Pick the right answer for today. The loss, (a − target)², measures how wrong the neuron is. The gradient says which way each weight should move to shrink it. Learning is a small step against the gradient.

0.30
The math: the chain rule

We want ∂loss/∂w₁, how much the loss changes when w₁ moves a tiny bit. The loss depends on a, which depends on z, which depends on w₁. The chain rule multiplies the three local slopes:

∂loss/∂w₁ = ∂loss/∂a × ∂a/∂z × ∂z/∂w₁
= 2(a − target) × (1 − a²) × x₁

(1 − a²) is the slope of tanh. When the neuron is stuck near ±1 that slope is close to 0, and learning slows down. Big networks apply the same rule backwards through every layer. That is backpropagation.

Training: thousands of tiny nudges

To learn, the model needs a score for how wrong it is. Language models use cross-entropy loss: loss = −ln(p), where p is the probability it gave the right next token.

0.50

Picture the loss as a landscape. Every setting of the weights is a spot on the ground, and height is the loss. The gradient points uphill, so each step goes the other way: w ← w − learning rate × gradient. That is gradient descent.

The math: one real training step, in numbers
The math: backpropagation for the whole network

These six lines are the complete gradient calculation in core.js, the code training your model. y is the correct token, ⊙ multiplies item by item, and ᵀ reads a weight table the other way round.

∂L/∂logits = p − onehot(y)
∂L/∂W₂ = (∂L/∂logits) · hᵀ   ∂L/∂b₂ = ∂L/∂logits
∂L/∂h = W₂ᵀ · (∂L/∂logits)
∂L/∂z = ∂L/∂h ⊙ (1 − h²)
∂L/∂W₁ = (∂L/∂z) · xᵀ   ∂L/∂b₁ = ∂L/∂z
∂L/∂x = W₁ᵀ · (∂L/∂z) → added to the 3 embedding rows used

The first line has a neat meaning. The right token's score is pushed up by 1 − p, and every other token's score is pushed down by its own p. These gradients were checked against small-step numerical estimates and agree to at least 8 decimal places.

Why our model gets confused

It only ever sees the last 3 tokens. Try "the cow sleeps in the": by the time it reaches "the", "cow" has dropped out of view, so it cannot know the answer is "barn". The amount of text a model can see is its context window.

Transformers fix this with attention. Every token looks back at all earlier tokens, scores how relevant each one is with the same softmax you saw in Chapter 5, and mixes in what matters.

From next-word guesser to ChatGPT

  1. Pre-training. What you did in Chapter 6, on a huge slice of the internet: predict the next token, measure the loss, backpropagate, nudge the weights. Billions of times.
  2. Instruction tuning. More training on example conversations written by people, so the model answers questions instead of just continuing text.
  3. Learning from human feedback (RLHF). People rank several answers. A second model learns to predict those rankings, and the chatbot is tuned to give answers that score well. OpenAI described this in its 2022 InstructGPT paper.

What you now know

  1. A language model guesses the next token. Writing is that guess, repeated.
  2. A tokenizer (BPE) turns text into token IDs using merges learned from data.
  3. Each ID becomes an embedding, a learned row of numbers that captures how the token is used.
  4. Neurons multiply by weights, add a bias, and squash. Layers of them make a network.
  5. Softmax turns scores into probabilities. Cross-entropy loss measures how wrong they were.
  6. Backpropagation finds every weight's gradient, and gradient descent nudges each one downhill.
  7. ChatGPT is this recipe with transformers, attention, vast data and human feedback.
